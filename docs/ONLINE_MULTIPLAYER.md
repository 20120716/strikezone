# STRIKEZONE オンライン化計画

この文書は将来の実装方針です。ここに書かれたオンライン機能は、まだ実装済みではありません。

## 推奨構成

- **フロントエンド:** いまの WebGL ゲーム。GitHub Pages から静的配信を続ける。
- **ゲームサーバー:** Node.js / TypeScript の独立したサーバー。プレイヤー位置、HP、弾薬、命中判定、ラウンド進行をサーバー側で管理する。
- **通信とルーム管理:** Colyseus を第一候補として検証する。ルーム作成・参加、プレイヤー状態の同期、切断時の処理を扱える。最終決定は小さな試作で通信遅延・費用・運用のしやすさを比較してから行う。
- **接続:** 公開環境では TLS 対応の HTTPS / WSS を使い、ゲーム本体とサーバーは別々にデプロイする。

GitHub Pages はゲーム画面などの静的ファイルを配信する場所として使い、リアルタイム対戦のサーバー処理は別サービスで動かす。

## 実装ステップ

### Phase 0 — シングルプレイの土台を安定させる
- [ ] 建物と遮蔽物の移動衝突・射線遮蔽を実機確認
- [ ] PC / iPhone / iPad で操作とパフォーマンスを確認
- [ ] マップの建物・障害物データを描画と衝突判定で共有する

### Phase 1 — クライアントをオンライン対応しやすく整理
- [ ] index.html のゲーム処理を描画、入力、ゲーム状態、ネットワークに分離
- [ ] ローカルプレイヤーと他プレイヤーを同じ描画インターフェースで描く
- [ ] ネットワーク接続がなくてもシングルプレイが動くように維持

### Phase 2 — 最小のオンライン試作
- [ ] Node.js / TypeScript サーバーの土台を作る
- [ ] 2〜4人の部屋を作成・参加・退出できるようにする
- [ ] プレイヤーID、位置、向き、HPを同期する
- [ ] 切断・再接続と、部屋が空になったときの処理を行う

### Phase 3 — 対戦ルール
- [ ] 移動可能範囲・移動速度・HPなどをサーバー側で検証
- [ ] 射撃要求を受けて、サーバー側で命中とダメージを確定
- [ ] リスポーン、ラウンド、スコアボードを実装
- [ ] クライアント側では他プレイヤーの位置を補間して表示し、通信の揺れを目立ちにくくする

### Phase 4 — 公開テスト
- [ ] 招待コードまたはルームコード
- [ ] 通信状態・Ping表示とエラー表示
- [ ] サーバーのログ、レート制限、不正な入力への対策
- [ ] モバイル回線と Wi-Fi で複数端末テスト

## オンライン化の基本ルール

1. クライアントは「こう動きたい」「この方向に撃った」という入力を送る。
2. サーバーが移動・命中・ダメージなどの最終結果を決める。
3. サーバーが状態を全員へ配信し、クライアントは滑らかに描画する。

最初から大規模なマッチメイキングやランキングを作らず、まずは友達同士で同じ部屋に入り、互いに見える最小構成を完成させる。
